## Constraints that bound every design choice
1. **The pipeline keeps working.** These stay allowed, as real `decide()` calls in the test: `bash core/harness/job.sh ...` (every subcommand, incl. `scratch <owner>`, `lock`, `status`, `ctl`), `python3 core/proxy/tools/pc_deploy.py ...` (install, uninstall, set, status),
   every `python3 core/wsc.py <verb>` (incl. `setup`, `gates`, `jobs`, `policy`, `reg set`), `git checkout -b job/<id> origin/main`, `git push` and `git push -u origin job/<id>|brief/<id>`, `git commit ... --trailer "Claude-Session: <id>"`,
   `gh pr create ...`, `gh pr view`, `gh pr ready`, `gh pr merge job/<id> --auto --squash` (the reviewer's D32 merge), `gh pr merge brief/<id> --auto --squash` (a writer's D33 merge), and deleting remote scratch branches
   (`git push origin --delete scratch/<x>`, `-d`, `:scratch/<x>`).
2. **Fast.** Stdlib only, no subprocess on the common path (the one exception is decision 8's `gh pr view`), no import beyond what is imported today, no scan of heredoc bodies except for an inline interpreter. Targets: `decide()` under 5 ms for a typical command,
   the whole hook process under 150 ms on the project PC; the tests assert generous bounds (the whole corpus in-process under 3 s; one hook subprocess under 1.5 s) and the report states the measured numbers.
3. **Fail closed where it matters, never wedge.** A hook bug or an unreadable `core/`/root file must not stop every shell call (J20 review: exit 2 blocks the call). The rule: an unreadable input switches off only the rule that needs it, and for the dangerous
   classes a conservative fallback applies instead (decisions 3 to 5). **The way out for the builder:** the Edit and Write tools are not matched by the hook (`matcher` is `Bash|PowerShell`), so a hook that denies too much can always be repaired with them.
   Two habits keep it that way: (a) after every edit to `tools/claude_hook.py`, pipe a sanity set through it (`git status`, `git commit -m x --trailer "Claude-Session: <id>"`, `git push`, `gh pr view`, `python3 core/wsc.py jobs check`) and see no `deny`;
   (b) edit `.claude/settings.json` **last** (step 8), after the hook and the corpus are green, because the wrapper change is the one edit that can wedge a session.

## Decisions already made (do not re-open; each has its reason)
1. **One parser, one evaluation order.** Replace the three regex entry points (`git_reason`, `write_reason`, the trailer test) by a single pass `units(cmd, cwd)` that yields every simple command with its argv, redirections, the tracked cwd and the tracked variables. Reason: all three
   gaps (H1, H6, trailer) are the same defect, a rule looking at the wrong slice of the command. Keep the public names the tests use: `decide(event, roots=None)`, `protected_roots`, `norm`, `resolve`, `ROOT`.
2. **What the parser unwraps** (recursion depth at most 4; deeper counts as unparseable, decision 4): separators `&& || ; | & newline`; leading `if then else elif do while until for..in ! { } ( ) time`; `( ... )`, `$( ... )`, backticks, `<( ... )`; `bash|sh|zsh -c '...'`, `eval '...'`, `cmd /c`,
   `powershell|pwsh -Command|-c '...'`, `Start-Process -FilePath/-ArgumentList`, `start`, `call`; wrappers `nice [-n N]`, `timeout [opts] N`, `env [-i] [-u X] [VAR=v]...`, `sudo`, `xargs`, `command`, `exec`, `nohup`, `time`, `stdbuf`, `setsid`, `ionice`.
   State (cwd, variables) flows left to right through the whole command with no subshell scoping: the conservative choice, because a false "unknown" is cheaper than a hole. Variables: `V=x`, `export V=x`, `$V = 'x'`, `$env:V = 'x'`, `set V=x`; expanded in `$V ${V} $env:V %V%`;
   an unknown one falls back to the hook's own `os.environ`, then stays unresolved.
3. **A command is "tainted" when its text, after expansion and 8.3 expansion, names a protected root** (any spelling `norm` accepts, plus the 8.3 forms `progra~1`, `napole~1`, `empire~1`, `napole~2` style). Unresolved cwd or unresolved target + tainted = **deny** ("cannot tell where this runs/writes, and the command names a protected folder").
   Unresolved + not tainted = allow, so `echo x > "$OUT"` and `cd "$(mktemp -d)" && git status` still work (this is the existing tested behaviour; open question 1 asks Liam to confirm). 8.3 names are expanded with `GetLongPathNameW` through `ctypes` on Windows, behind an injectable `expand_short` so the Linux CI tests can stub it;
   a component that matches `\w{1,6}~\d` and cannot be expanded counts as unresolved.
4. **Per-segment exemption (H1).** `EXEMPT` is dropped as a whole-command switch. A segment is exempt from the *write* rule only when its command word, after wrappers and `python3`/`bash`/`sh`, is a script that resolves to this checkout's `core/proxy/tools/pc_deploy.py` or `core/harness/job.sh`
   (relative to the tracked cwd, or absolute under `ROOT`, or `harness/job.sh` inside a core checkout); a look-alike at another path (`/tmp/pc_deploy.py`) is not exempt. The exemption covers the script's own writes only: **the segment's redirections are still checked**, and every other segment of the command is judged on its own.
   So `pc_deploy.py status; rm -rf <state>/watcher` is denied at the `rm`. The git rule and the launch/kill rule have no exemption (nothing sanctioned runs git or the game from a shell call, except `job.sh`, which is the sanctioned launch route and is an exempt command word for the launch rule only).
5. **Writers added** (value = which arguments are written): `install` last (or `-t`, `-D`), `rsync` last, `dd` the `of=` value, `tar` the `-C`/`--directory` folder when extracting (`x`) and the `-f` archive when creating (`c`/`r`/`u`), `ln` last (the link), `robocopy` second positional (and `/MOVE`, `/MIR` count as deletes there),
   `xcopy` last, cmd `copy` last, `move`, `ren`/`rename`, `del`/`erase`/`rd`/`rmdir` (cmd), `Rename-Item`, `Set-ItemProperty`, `Clear-Content`, `New-Item`, `ni`, `rni`, `Out-File`, `Tee-Object`, `truncate` all, `chmod`/`chown`/`mklink` last, `cat > f` as a redirect.
   Redirections are scanned by a small tokenizer, not one regex: `>`, `>>`, `>|` (noclobber), `&>`, `&>>`, `>& file`, `<>`, `N>`, `N>>`, PowerShell `*>`, `>` forms; `>&2`, `2>&1`, `>&-` are descriptor duplications, not files; `exec 3>f` and `: > f` count.
   Inline interpreter code (`python3|python|py -c`, `node -e`, `perl -e`, `ruby -e`, `powershell|pwsh -Command|-EncodedCommand`, and a heredoc fed to `python3 -`) is **denied when it names a protected root (or an unexpanded variable while tainted) together with a write verb**
   (`open(...,'w'|'a'|'x'|'+')`, `.write`, `write_text`, `shutil.`, `os.remove|rename|replace|unlink|rmdir|makedirs|mkdir|system|popen`, `subprocess`, `rmtree`, `Remove-Item`, `Set-Content`, ...). A read-only snippet that names a root is allowed. `python3 some_script.py` stays allowed (the hook cannot know what a script does: a documented residual, in the header).
6. **Git (H6).** A unit whose command word (after wrappers and unwrapping) is `git`/`git.exe`, in any nesting, is denied when **any** of these resolves into a protected root: the tracked cwd, `-C`, `--git-dir`, `--work-tree`, `GIT_DIR`, `GIT_WORK_TREE`, `-c core.worktree=`, `-c core.hooksPath=`, any positional argument of `init`,
   `clone` (destination, the last positional), `worktree add`, `submodule add`, `--separate-git-dir`, or the cwd is unresolved while tainted (decision 3). The old `git_reason` special cases are subsumed; the existing `test_git_in_a_protected_root_is_denied` and `test_git_elsewhere_passes` fixtures keep passing unchanged.
   The trailer rule moves to the same pass: find the subcommand by skipping git's global options (`--no-pager`, `-P`, `-p`, `--paginate`, `--bare`, `--no-optional-locks`, `--no-replace-objects`, `--literal-pathspecs`, `--exec-path[=x]`, `--namespace x`, `--git-dir[=x]`, `--work-tree[=x]`, `-C x`, `-c k=v`, `--config-env=x`);
   if it is `commit`, or an alias of it (an alias from `-c alias.X=...` in the same command, or from `[alias]` in `~/.gitconfig`, `$XDG_CONFIG_HOME/git/config` and the repo's `.git/config` read as plain text, cached per process, size-capped; a value whose first word is `commit` or that is a `!` shell alias containing `git commit`),
   rewrite it to the canonical `git commit <args>` and call the core's `commit_lacks_trailer` on that. Setting such an alias (`git config alias.X commit...`, `-c alias.X=commit`) is denied. `git commit-tree` and `git log --grep commit` stay allowed (existing fixtures).
7. **Redirections of an exempt segment are checked, so one existing fixture changes.** `test_reads_scratch_and_the_sanctioned_writers_pass` has `bash core/harness/job.sh j18 - <<< "launch owner=j18" > <state>/x.log`, which writes into the state folder through a redirect and was only allowed because of the whole-command exemption. Move that fixture's redirect to
   `/tmp/x.log` and add the original shape to the denied list. Reason: it is exactly H1's bypass. If a real job step turns out to print a redirect into the state folder (step 6 checks), stop and apply the kill criterion: do not weaken the rule.
8. **D50 merge rights (P6).** Parse `gh pr merge` (and `gh pr merge` behind wrappers, `bash -c`, `gh` with `-R/--repo`) and `gh api` calls to `.../pulls/<n>/merge` or `PUT .../merge` or the `mergePullRequest`/`enablePullRequestAutoMerge` GraphQL mutations.
   `gh pr merge <target>`: strip `origin/`, `refs/heads/`, `owner:` prefixes; a target matching `^(plan|meta)/` is **denied**, a target matching `^(job|brief)/[A-Z]\d+$` is allowed. A number, a URL or no target (current branch, from `git branch --show-current` in the tracked cwd) is resolved to its head branch with
   `gh pr view <target> [-R repo] --json headRefName -q .headRefName` (timeout 5 s; this is the only subprocess in the hook, and only for these rare shapes); a resolved `plan/` or `meta/` is denied, any other branch is allowed, and **an unresolvable target is denied** with the message to re-run with the branch name (fail closed; the pipeline's printed commands always name the branch).
   `gh api` merge calls are denied outright (nothing in the pipeline uses them). The repository is not checked: warscape-core's `plan/` and `meta/` branches are Liam's as well. The message cites D50 and says Liam merges. Branch kinds other than the four (for example `scratch/*`, `main`) are allowed here; GitHub's rulesets cover them.
9. **Remote branch deletion.** `git push <remote> --delete|-d <branch>...`, `git push <remote> :<branch>` and `gh api -X DELETE .../git/refs/heads/<branch>`: allowed for `scratch/*`; denied for `main`, `plan/*`, `meta/*`, `job/*` and `brief/*` (the pipeline never deletes them; GitHub deletes merged branches), allowed for any other name. Reason: the audit's chore row only needs `scratch/*`,
   and a positive rule with a few named denials is a small, testable change. Open question 3 asks Liam about the denials.
10. **`--no-verify`.** Denied on `git commit`, `push`, `merge`, `rebase`, `cherry-pick`, `am`, including `commit -n` and clusters (`-an`, `-nm "x"`: scan the cluster left to right and stop at an argument-taking letter `m F C c t u S`), and `-c core.hooksPath=<anything>` on those subcommands. `git config core.hooksPath core/.githooks` (CLAUDE.md's one-time setup) stays allowed.
11. **Game launch and kill (H6).** Image names come from `adapter.json` (`game_image`, `other_images`), not literals. Denied: a command word (after wrappers) equal to an image, or an image / `steam://` URI as the target of `start`, `Start-Process`, `Invoke-Item`, `explorer`, `cmd /c`, `rundll32 url.dll`, `xdg-open`, `steam.exe -applaunch`; `taskkill`, `Stop-Process`, `pkill`, `killall`, `wmic process ... delete` when the command names an image,
    and `Get-Process ... | Stop-Process`. A plain `kill <pid>` is allowed (agents stop their own background servers). `job.sh` stays the launch and kill route. Reading the exe (`sha1sum`, `ls`, `cat`, `pc_deploy.py status`) stays allowed. The deny message says: launch and kill only through `core/harness/job.sh` (CLAUDE.md "Where agents run").
12. **Fail closed, not wedged (R11/H1 rows `:191-195`, `:212-216`, the settings wrapper).**
    - Roots unreadable (`protected_roots` raises): use a conservative fallback pattern, not a copy of the values: any path under a drive's `program files*`, `steamapps`, `napoleon_remastered_pc` or a `*total war*` folder is protected, state folder unknown (so no `_scratch` allowance: those commands are denied with a message that names the file to repair). Every other rule keeps running. The deny text ends with "protected roots unreadable: restore harness/napoleon/adapter.json and discovery/napoleon/games.json".
    - `core/` unreadable (the import fails): `git commit` is denied with "run git submodule update --init" (the command that fixes it is a `git submodule`, not a commit, so it is allowed); nothing else changes.
    - `main()` catches an exception from `decide()` and falls to `panic()`: a tiny independent screen over the raw command text that denies only (a) a `git ... commit` with no `Claude-Session` text and (b) the conservative pattern above together with a write, git, launch or kill word; everything else is allowed and the traceback goes to stderr. Never a non-zero exit from the python process.
    - The settings wrapper reads stdin once, runs `timeout 10 python3 "$f"` (fall back to `python`, then `py -3`, if `python3` is not found), and when python is missing, crashes or times out (non-zero exit) it applies the same panic screen with `grep -Eiq` on the saved stdin and prints the deny JSON with `printf`; otherwise exit 0. A missing hook file still exits 0 (a branch cut before J20 has no hook; CI's `policy` still refuses its commits).
13. **Settings deny rows.** Add `Edit(//c/napoleon_remastered_pc/ctl/**)`, `.../play/**`, `.../saves/**`, `Edit(~/AppData/Roaming/The Creative Assembly/Napoleon/scripts/preferences.script.txt)` and `.../Napoleon/save_games/**` (the prefs file and the save folder; `config_files` in `adapter.json` names the prefs path). The hook treats the AppData prefs file and `save_games` as **write-protected paths** too
    (shell writes denied with "use saves/napoleon/stage_save.py or pc_deploy.py set"; git there is not special), so the shell is not a way round the Edit rows; the paths come from `adapter.json` `appdata_dir` with `%APPDATA%` expanded from the environment. The settings test derives the new rows from `adapter.json` the way `test_settings_deny_edits_in_the_other_game_and_the_managed_state` does.
14. **Denial text.** Every new denial says what it saw, which rule, and the sanctioned route, in the style of the existing three; one test asserts each family's message contains its route (`pc_deploy.py`, `job.sh`, `D50`, `git submodule update --init`, ...).
