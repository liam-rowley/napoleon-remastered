## Desk steps
Write each test first and keep the red output for the report.
1. **G5a, owned is the union of every installed set** (`rr.ps1`, `Do-Install`, the `$rec['owned'] = @($script:Man['owned'])` lines at install end and in the new-record literal). An upgrade must set `rec.owned` to the sorted union of the old record's `owned` and the manifest's, so a file an older release owned (a DXVK file, a pack renamed in 0.2.0) is still moved at uninstall. Also keep it in `Do-Repair` if repair rewrites the record. Test `test_upgrade_keeps_the_old_release_owned_set`: install release A (builds with the `make_kit`/release helpers; build A and B in the test with B owning a different file set), run B's `Install.cmd`, add the runtime file A owned, uninstall: exit 0, game folder identical to the pre-install snapshot, no leftover A file.
2. **G5b, back up on every install** (`rr.ps1:245-266`). The backup loop sits inside `if ($null -eq $rec)`, so a re-run after a failed first install (record exists, backups half done) skips it and `Move-Out` then sends a foreign file at an owned path to `_to_delete` as ours. Move the loop out of the `$null -eq $rec` branch and run it on every install, over the union set, for each owned path that exists and is not one of this installer's own files (a path is ours when the record lists it in `files` with the recorded sha256 and it still hashes the same; a copy that differs is foreign: back it up). Backups already recorded are not repeated (match on `path`). Test `test_rerun_after_a_failed_install_backs_up_foreign_files`: kill the first install after the first backup entry (a `-FailAfter` style test switch is not allowed in the shipped script: do it by pre-writing an `install.json` with a half-done `backups` list and a foreign file at a later owned path), run install, uninstall: the foreign file is restored byte for byte and not found under `_to_delete`.
3. **G7, Steam update then uninstall** (`rr.ps1:92-108, 328-331`). After a Steam update every updated vanilla file differs from the pre-install snapshot, so uninstall always printed DIFFERS and returned 1 although the mod was removed. When the exe verdict after the uninstall is MISMATCH (the exe sha1 no longer matches `exe_identity.json`), classify each diff outside the owned set and outside the backups as `steam-update` and print it under its own heading ("changed by the game update, not by this tool"), exit 0 when the owned files and backups are restored and only such diffs remain; with the exe verdict vanilla, the current strict DIFFERS and exit 1 stay. Diffs at owned or backed-up paths are never reclassified (those are ours). Record `identical=false` plus `steam_update_diffs` (count) in the history entry. Tests: `test_uninstall_after_a_steam_update_exits_0` (install, then change the synthetic exe and a vanilla pack, uninstall: exit 0, the heading present, the exe verdict printed MISMATCH, owned files gone, backups restored) and the existing `test_uninstall_reports_a_difference` must stay green (exit 1 on a changed pack with a vanilla exe). Both tests assert the exit code, which the audit says the old test never did. Update the README and the `Uninstall.cmd` closing text so the promise matches.
4. **G6, `_to_delete` cleanup** (`rr.ps1:120-129, 272, 307, 416`). `Move-Out` copies and removes across drives, so each install, repair or uninstall leaves about 1.8 GB in `%LOCALAPPDATA%\napoleon_remastered\_to_delete`. (a) A `Clean` verb in `rr.ps1` and a `Clean.cmd` generated like the other `.cmd` files by the builder (same ASCII/CRLF rules, same components extras route as `Support.cmd`): it lists each `_to_delete` stamp folder with its size, asks `Delete these? [y/N]` (`-Yes` skips the prompt for tests, `-NoPause` as elsewhere), deletes only inside `<state>\_to_delete`, refuses while the game runs, and never touches `backup\`, `snapshots\`, `history\` or `install.json`. The installer is the player's tool and deletes on the player's PC after confirmation; the "never delete" rule is for the agents' PC folders and is not changed. (b) A closing line at the end of install, repair and uninstall: `rr: _to_delete holds <size> in <n> folders: run Clean.cmd to free it`. Tests: `test_clean_removes_only_to_delete_after_confirmation` (answer no: nothing removed, exit 0; `-Yes`: stamp folders gone, `backup\`, `snapshots\`, `install.json` untouched) and `test_uninstall_prints_the_to_delete_size`. Add `Clean.cmd` to the builder's installer files, the `--check` folder rule and the release smoke test in `tests/test_release.py`.
5. **G14a, the sidecar** (`build_release.py:94-96` area, the external build output check). An external build output (the proxy DLL, packs built elsewhere) passes today when its `.json` sidecar is missing. Refuse it: the sidecar must exist, name the same sha256 as the file and the build id the release pins. Test in `tests/test_release.py`: missing sidecar, sidecar with another sha256, both refused; the real release still builds clean (`test_real_release_is_clean`).
6. **G14b, `--record`** (`build_release.py`, `release/napoleon/releases.json`). `releases.json` is hand-edited, so the builder rebuilds 0.1.0 with different content until Liam publishes. Add `--record`: after a successful build it writes the version, the manifest sha256 and the build id into `releases.json`; a later build of a recorded version whose manifest sha256 differs is refused ("0.1.0 is recorded with another content: bump `VERSION` or pass `--rebuild-unreleased`"), and `--rebuild-unreleased` is the only way to overwrite an entry not yet marked published. Never record without Liam: `--record` is a flag, not a default, and the builder still never publishes. Tests: record then rebuild identical (passes), rebuild with a changed file (refused), `--rebuild-unreleased` (passes, entry updated).
7. **G14c, dead code** (`build_release.py:94`). Delete `key_text()` (it imports `gen_tables`, nothing calls it: grep first and say so in the report).
8. **G14d, one discovery story** (`build_release.py:352`, `rr.ps1:143-149`, `release/README.md`). `Find-Game` searches upward from the release folder first, so the README's "unzip anywhere EXCEPT inside the game folder" contradicts the code. Decide by the safer rule and make both say it: keep the upward search (a player who unzips inside the game folder still works), and change the text to "Unzip this folder anywhere; if it sits inside the game folder, the installer still finds the game, but verify-and-reinstall in Steam deletes it, so keep a copy elsewhere". Change the generated README.txt, the README and the `Find-Game` comment together; test that the generated README.txt contains no "EXCEPT" and that the existing `test_finds_the_game_from_the_scripts_own_location` still passes. The second discovery copy (`tools/verbs/discovery.py`) and the PC paths in the `uiscale` and `upscale` verbs are not here: J64 and J79 own them.
9. Run `python3 core/wsc.py gates` and the three installer modules (`python -m unittest -v tests.test_release_installer tests.test_release tests.test_play`); CI runs the installer step on Windows.
