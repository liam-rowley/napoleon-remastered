# J11 report: Discovery gate

Built: `wsc discovery gate` (`discovery/core/gate.py`), which checks every registry is populated and current (floors, row shapes,
an index pin and pack fingerprints, recomputed currency, a ratchet on the known gaps, a read-only `--install` comparison with the
game), and the J5 row 80 found-path rule (`discovery/core/briefpaths.py`), run by `jobs check` on every brief that is not in the
frozen legacy set. Both are in the `tests` gate through real-repo tests. Branch `job/J11`.

## What was built
- **Found-path rule** (J5 ledger row 80), `discovery/core/briefpaths.py` (tool `discovery.core.briefpaths`).
  - `found_path_problems(text, known)` is pure; `load_known(root)` builds `known` once per process from the committed index, the
    `assets` and `ui_elements` registries, and `git ls-files`.
  - It flags four shapes: the extract store; a backslash (pack-form) path under a game folder; a path under a game folder that is
    not an `assets` id, `ui_elements` id or tracked repo file or directory; and a layout or script path a `ui_elements` unit holds in
    `vanilla_source` (the error names the unit id).
  - Exemptions: a `Quoted, not a citation:` line above a fence or starting a bullet; an `Evidence base` paragraph; `<>`, `*`, `{}`
    placeholders and globs; and `## Registry gaps` bullets of the form `path: P; owner: <J<n>|liam>; reason: R` (a bullet missing an
    owner or a reason is an error). Errors read ``line N: `token` is a found path: ...``. `registry_gaps` parses the hatch.
- **Hook in `jobs check`** (`tools/verbs/jobs.py`, +33/-6).
  - `brief_problems(..., known=None)` runs the rule for any brief not in the frozen `LEGACY_BRIEFS` (the 52 briefs at base
    c674fb1, plus `LATE_LEGACY = {J24, J37}`, which merged before J11). `problems(..., known=None)` passes `known` through and `run`
    builds it. `jobs check` now prints "N registry gaps in briefs" (0 today).
  - `brief_steps` (what a brief writer is shown) carries three lines on how a brief cites (the brief's item 6).
- **Gate** (`discovery/core/gate.py`, tool `discovery.core.gate`; `wsc discovery gate [--install] [--write] [--json OUT]` in
  `tools/verbs/discovery.py`). It checks:
  1. a floor per registry (9) and per `ui_elements` context (6);
  2. row shapes: `ui_elements` at `atlas` or later with a layout or script and interactions; `engine.*` rows start with `route:`
     (D39); `engine_sites` have a verified date and run and the pinned exe sha1; `config_keys` owner is a job, `liam` or a named
     component; `scenarios` have a launch recipe; open `engine_facts` name a job or `liam`;
  3. the index pin and pack fingerprints (offline);
  4. recomputed currency: J6 area files, READMEs, the `assets` registry against index/refs/roles (`j7_problems`), atlas sha256s
     (`ui_problems`), `reg check` (which also covers tools rows and files), `hotkeys check`, and `gen_tables --check` for `engine_sites`;
  5. a ratchet on the findings, and a gate-summary-current check.
  - `--install` (read-only, PC) compares each pack's entry count and entry-byte sum with the recorded fingerprint, `pack_order`,
    extra packs, and the `Napoleon.exe` sha1 with `proxy/napoleon/identity.json`. Offline it prints "warn install not compared" and
    never an ok for it.
  - `wsc discovery check` now includes the gate; the duplicate currency code on the old `check` path is removed.
- **Data:** `discovery/napoleon/gate.json` (floors, ratchet, pinned index, `config_key_owners`). The index is pinned by the sha256
  of the inflated text, not the gzip bytes (they differ between zlib builds; the existing `tsvgz` caveat).
  `discovery/gate/summary.json` is deterministic, with no counts that move with routine work; `discovery/gate/README.md` is
  generated by `discovery render`. `assets.pack_fingerprints(index)` is new and called by `summarise`; its output is written into
  the committed `discovery/assets/summary.json` from the committed index, without re-running a pass.
- **Four open `engine_facts`** got "Owner: liam" in their notes (`wsc reg set`): `napoleon.campaign.camera_route`,
  `napoleon.campaign.quit_to_menu`, `napoleon.harness.kill_slow_once`, `napoleon.steam.installscript_vdf_mtime`. Claims unchanged.
- **Tools rows:** `discovery.core.briefpaths` and `discovery.core.gate` added; `wsc.discovery` updated.

## Deviations
1. **`config_key_owners: ["proxy"]` in `gate.json`.** The brief says every `config_keys` owner must resolve to a job or `liam`;
   31 of 38 rows have owner `proxy` (a component). Failing them would have meant editing registry data beyond the four notes, which
   the brief forbids. The allowed component names are listed in `gate.json`; any other unresolved owner is still rejected (tested).
2. **Index currency** is a pin in `gate.json` (sha256 of the inflated text, row count, build date), plus a check that the
   `summary.json` row count and fingerprint match: the atlas and registry rows cite no index sha. A new index needs a `gate.json` commit.
3. **Fingerprint contents:** pack file sizes are recorded nowhere, so the fingerprint is per pack: entry count plus sum of entry
   sizes, from the committed index and comparable with the installed pack's own index.
4. **Gate summary content:** `discovery/gate/summary.json` holds only the stable discovery-derived gaps, the index pin and the
   assets-summary sha; registry counts, the open-fact count and brief gaps are printed live and ratcheted from `gate.json`, so routine
   registry additions and concurrent jobs (J57) do not turn `discovery check` red.
5. **Ratchet:** a gap above its recorded number fails; one below prints a "lower gate.json" note only.
6. **"How a brief cites"** went into `brief_steps` (code every brief writer is shown), not a prose doc.
7. **The tools gate is not called separately:** `reg check` already includes it.
8. **`jobs.py` footprint** is bigger than minimal only through the `LEGACY_BRIEFS` literal; J57 touches the same file (expect a
   trivial merge).
9. **`--install` not run** against the real game: tested on a synthetic tree only. The first PC sitting should run
   `python3 core/wsc.py discovery gate --install` once (read-only) and record the dated result.
10. **Report written by the orchestrating chat:** the build ran as a subagent whose harness refuses writing report files; the
    orchestrating chat (same Claude-Session) wrote this from the subagent's text, with Liam's approval (2026-11-02).
