## Desk steps (no game)
1. **Round DXT targets up to a multiple of 4 (J50 Later 2).** `rules.target_size` stays the plain 2.5x. Add `rules.dxt_target_size(w, h, fmt, scale)` (or a `fmt` argument to `decide`): for a DXT1/2/3/5 source, round each axis of the target up to the next multiple of 4 (460x152 gives 1150x380 gives 1152x380). First list the affected files with `plan` against the assets registry (J50 counted 6; record the real list). `batch.run`, `batch.plan` and `verify_entry` (which asserts the manifest target equals `rules.target_size`) all use the one function. The rule is built unconditionally; PC step 2 says whether the engine needed it. Tests: the rounding; `verify` accepts a rounded DXT output and refuses a plain-2.5x one; non-DXT files unchanged.
2. **`verify` checks the premultiplied invariant for DXT2 (J51 Later 3).** In `verify_entry`, for `fmt == 'DXT2'`, decode each level as DXT3 (raw, no unpremultiply) and require `max(R,G,B) <= A + tolerance` (8 of 255, for 5:6:5 colour quantisation); report the count of texels above it. Tests: a synthetic DXT2 passes, one with colour above alpha fails, DXT3 is not checked.
3. **`plan` estimates output bytes and `run` refuses below 20 percent free (J51 Later 2).** `batch.plan` adds, per role and in total, the estimated output bytes (target w x h x bytes per texel x 4/3 for a DDS mip chain; for TGA and JPG a per-format ratio measured from the J51 run records under `upscale/runs/`, stated), the free bytes on the work drive and the free percent after the run. `cli.py run` refuses (exit 2, one line with the numbers) when the work drive would keep under 20 percent free; `--force-disk` overrides and is logged. Tests with a stubbed free-space function; report the estimate against the real J51 output size for the roles whose runs are on record (aim within 25 percent).
4. **`run` appends its summary to a log in the work folder (J51 Later 5).** One line per run (UTC time, roles, done, fresh, skipped, failed, seconds, whether `--force-disk` was used) appended to `<work>\run.log`, so a resume pass leaves its numbers. Test: two runs leave two lines.
5. **Docs and gates.** `upscale/README.md` gets the new rule, the free-disk guard and the log where it already describes the size rule and `run`; the tool headers (`rules.py`, `batch.py`, `cli.py`) stay accurate. `python3 core/wsc.py gates` green.
